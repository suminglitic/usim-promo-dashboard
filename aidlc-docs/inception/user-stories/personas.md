# User Personas

## Persona 1: 요금제 분석가 (Plan Analyst)

| 항목 | 내용 |
|------|------|
| **이름** | 김민수 |
| **역할** | 요금제 기획/분석 담당자 |
| **부서** | 마케팅전략팀 |
| **기술 수준** | 중급 (엑셀/데이터 분석 가능, 개발 경험 없음) |
| **주요 목표** | 경쟁사 요금제 프로모션 변동을 빠르게 파악하여 자사 대응 전략 수립 |
| **사용 패턴** | 매일 아침 출근 후 대시보드 확인, 프로모션 변경 감지 시 수시 접속 |
| **Pain Points** | 현재 수동으로 3사 사이트를 일일이 방문하여 비교 → 시간 소모, 누락 발생 |
| **Success Criteria** | 5분 이내에 3사 요금제 현황 파악 완료 |

## Persona 2: 팀 리더 (Team Leader)

| 항목 | 내용 |
|------|------|
| **이름** | 박지영 |
| **역할** | 마케팅전략팀 팀장 |
| **부서** | 마케팅전략팀 |
| **기술 수준** | 초급 (대시보드 조회만 가능) |
| **주요 목표** | 주간 회의 시 경쟁사 동향 요약 보고, 트렌드 기반 의사결정 |
| **사용 패턴** | 주 1~2회 접속, 트렌드 차트 위주 확인 |
| **Pain Points** | 팀원에게 매번 데이터 요청 → 보고 지연 |
| **Success Criteria** | 직접 대시보드에서 트렌드 확인 후 즉시 의사결정 가능 |

## Persona 3: 시스템 운영자 (System Operator)

| 항목 | 내용 |
|------|------|
| **이름** | 이준호 |
| **역할** | 크롤링 시스템 관리/모니터링 |
| **부서** | 마케팅전략팀 (겸임) |
| **기술 수준** | 상급 (Python, AWS 경험 있음) |
| **주요 목표** | 크롤링 시스템이 정상 동작하는지 확인, 실패 시 원인 파악 |
| **사용 패턴** | 대시보드에서 마지막 수집 시간 확인, 이상 시 Lambda 로그 점검 |
| **Pain Points** | 크롤링 실패를 늦게 인지하면 데이터 공백 발생 |
| **Success Criteria** | 대시보드에서 데이터 수집 상태를 즉시 확인 가능 |
